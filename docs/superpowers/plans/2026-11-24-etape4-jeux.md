# Étape 4 — Jeux en un clic (et rôle de bump en règle) : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `site_games` devient la seule source des jeux : ajouter un jeu dans l'admin crée son rôle, son forum réservé et sa commande `/<jeu>` ; désactiver archive ; le message de rôles par réaction suit la liste des jeux. En prélude, le rôle de bump devient une règle automatique (demande du propriétaire).

**Architecture:** Colonnes ajoutées à `site_games` (migration 023) ; un cog `GameManager` remplace `GAMES` (game_lfg.py) et `GAME_ROLES` (reaction_roles.py), provisionne rôle/forum/commande et enregistre dynamiquement les commandes de jeux (commandes de serveur, synchronisation regroupée) ; l'API interne du bot expose provisionnement/archivage ; web-api et la page `/admin/jeux` pilotent le tout. Réglage `staff_roles` partagé (forums de jeux aujourd'hui, modèles de salons à l'étape 5).

**Tech Stack:** PostgreSQL 15, discord.py (app_commands dynamiques), FastAPI, Next.js 16 / vitest, pytest.

**Spec:** `docs/superpowers/specs/2026-11-23-pilotage-discord-design.md` §4.1, §4.4 (règles), §4.5 (jeux, réactions, staff_roles).

## Global Constraints

- Droit du site : `games.manage` (jeux) ; `settings.manage` + réservé admin pour `staff_roles` (réglage qui désigne des rôles, règle de l'étape 2).
- Forum d'un jeu : visible et accessible **seulement** au rôle du jeu, aux rôles `staff_roles` et au bot (`@everyone` : `view_channel = False`) — décision du propriétaire.
- Nom de commande : `^[a-z0-9_-]{1,32}$`, unique parmi les jeux et différent de toute autre commande du bot (refus 422 français).
- Bascule sans changement visible : les 6 jeux de `GAMES` (dbd, lol, warframe, overwatch, fortnite, minecraft) gardent leurs commandes, cooldown (3600 s), emojis (🔪 ⚔️ 🚀 🌀 🏹 ⛏️) ; rôles et forums existants rattachés **par nom** au premier démarrage (aucune création). Un jeu présent dans `site_games` sans entrée `GAMES` (War Dogs) reste **non provisionné** jusqu'à ce qu'un admin clique « Créer le rôle, le forum et la commande ».
- Désactiver un jeu : retire la commande, archive le forum (verrouillé et masqué au rôle du jeu), garde le rôle ; réactiver restaure. Supprimer le rôle d'un jeu = action séparée de l'étape 3.
- Synchronisation des commandes de serveur regroupée : au plus une synchronisation toutes les 60 s, quelle que soit la rafale de changements.
- Rôles de notification du message de réactions (⭐ 📺 🎭) inchangés.
- Rôle de bump : règle `bumps ≥ bump_role_threshold → bump_role` ; le code codé en dur de `bump_tracker.py` est retiré ; les réglages `bump_role`/`bump_role_threshold` deviennent « Remplacé par les règles automatiques » (même traitement que Batman à l'étape 3).
- Journalisation de chaque action dans `audit_events` (kind `game`, source `site`). Erreurs Discord traduites en français. Ne jamais afficher `.env` ni `docker compose config`. Commits en français terminés par la ligne Co-Authored-By de la consigne.

## Review Focus

1. Deux jeux avec le même nom de commande, ou un nom égal à une commande existante (`/rang`, `/blague`…) → 422 (Task 3/4).
2. Forum ou rôle d'un jeu supprimé à la main dans Discord → l'admin affiche « à recréer », un clic recrée ; pas d'erreur en boucle (Task 3).
3. Ajout de 5 jeux d'affilée → une seule synchronisation des commandes dans la minute (Task 3).
4. Emoji invalide (texte, plusieurs emojis) → 422 ; emoji déjà utilisé par un autre jeu ou un rôle de notification → 422 (Task 4).
5. Le seuil de bump modifié sur la règle s'applique au prochain bump, sans autre réglage (Task 1).

**Interfaces:**
- Produces (`bot/utils/games.py`) : `COMMAND_RE = r"^[a-z0-9_-]{1,32}$"` ; `def validate_command_name(name: str, taken: set[str]) -> str | None` ; `def validate_emoji(value: str, taken: set[str]) -> str | None` (un seul emoji Unicode ou un emoji personnalisé `<:nom:id>`) ; `def forum_overwrites(everyone, game_role, staff_roles, bot_member, archived: bool) -> dict` (`@everyone` invisible ; rôle du jeu voir/écrire, ou voir seulement et `send_messages_in_threads=False` si archivé ; staff voir/gérer les fils ; bot tout).
- Produces (cog `GameManager`) : `async def reload()` (relit `site_games`) ; `async def provision(key: str) -> dict` (rôle : réutilise `discord_role_id` ou un rôle du même nom, sinon crée ; forum : idem dans la catégorie `game_forums_category` ; écrit les ids, `provisioned = TRUE` ; enregistre la commande) → `{"role_id", "forum_id", "command": str | None, "created": [..]}` ; `async def archive(key)` / `async def unarchive(key)` ; `async def resync_permissions() -> int` (réécrit les surcharges de tous les forums de jeux, renvoie le nombre) ; enregistrement dynamique : une `app_commands.Command` par jeu actif, ajoutée/retirée de `bot.tree` pour le serveur, `tree.sync(guild=…)` regroupée (minuterie 60 s) ; au démarrage, rattachement par nom des rôles/forums des jeux `provisioned` sans id (aucune création).
- Statut par jeu exposé : `{"role": "ok"|"missing", "forum": "ok"|"missing", "command": "ok"|"missing"|"none"}`.
